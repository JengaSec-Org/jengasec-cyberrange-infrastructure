# Observability development stack

This directory is the runnable development foundation for JengaSec
observability. Docker Compose starts a reference workload, Vector, Loki,
Prometheus and Grafana in a Codespace or a Debian 12 development VM. It does
not connect to or change Server 3.

## Data flow

```text
reference workload stdout -> Vector -> normalised telemetry JSON -> Loki
reference workload /metrics -------------------------------> Prometheus
Loki + Prometheus ------------------------------------------> Grafana
```

Vector discovers only containers carrying the
`jengasec.observability.collect=true` label. The Docker socket mount is a
development-only discovery mechanism and grants Vector powerful local access,
even though it is mounted read-only. A k3s deployment must replace the
`docker_logs` source with `kubernetes_logs` and use Kubernetes RBAC; the
normalisation transform and telemetry contract remain the same.

## Contract mapping

The reference workload writes one object per stdout line that passes
`contracts/logging-contract.schema.json`. Vector constructs a fresh object so
the result also passes the stricter `additionalProperties: false` rule in
`contracts/telemetry-event.schema.json`.

| Telemetry field | Source |
|---|---|
| `event_id` | UUID generated by Vector |
| `ts` | application `ts`, parsed as RFC 3339 |
| `received_ts` | Vector receipt time |
| `enterprise` | deployment setting `JENGASEC_ENTERPRISE` |
| `cell` | application `cell` |
| `source` | `application` for this pipeline |
| `event_type` | application `event` |
| `severity` | application value, or a level-based default |
| `actor`, `target`, `outcome` | mapped contract fields |
| `metadata.original` | the complete accepted application event |

Invalid input is dropped by the remap transform and counted in Vector's
internal metrics. Loki labels only bounded fields; event IDs and request IDs
stay in the JSON body to avoid high-cardinality indexes.

## AI integration boundary

There is deliberately no AI ingestion sink. The accepted AI OpenAPI contract
defines read-only telemetry endpoints but no producer ingestion endpoint, so
the old example URI `/api/v1/ingest` was not a valid contract. Loki is the
development event store until the AI and Observability owners agree whether
the AI service will read from Loki or accept events through a new authenticated
contract. That decision and any new endpoint require a contract pull request.

See `runbooks/observability-codespaces.md` for startup, validation, recovery
and shutdown commands.
